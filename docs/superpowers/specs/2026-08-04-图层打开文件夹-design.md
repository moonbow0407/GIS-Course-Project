# 图层右键"打开文件夹"功能设计

日期：2026-08-04
状态：已确认

## 需求

图层管理面板中右键图层时，菜单新增"打开文件夹"项：点击后在操作系统中打开该图层数据文件所在的文件夹。

## 现状与关键事实

- 图层右键菜单位于 `app/presentation/widgets/layer_panel.py` 的 `_on_context_menu_requested`（现有项：缩放至图层、符号系统、打开属性表、删除图层），面板不直接调用业务层，通过 Signal 请求主窗口处理。
- `VectorLayer.source_path` 与 `RasterLayer.source_path: Path | None` 已存在，`WorkspaceSnapshot` 的 `LayerSnapshot.layer` 可直接读取。
- 各类图层 `source_path` 情况：
  - 文件图层（geojson/shp/tif）：有路径。
  - 缓冲分析结果图层（project_data 下 gpkg）：有路径。
  - 数据库图层、尚未导出的数字化临时图层：无路径（None）。

## 设计（方案 A：面板发信号 + 主窗口处理）

### 1. `layer_panel.py` — 菜单项与信号

- `_on_context_menu_requested` 中新增 `menu.addAction("打开文件夹")`（置于"打开属性表"之后、"删除图层"之前）。
- 新增信号 `layer_folder_requested = Signal(str)`（携带 layer_id）。
- 选中该菜单项时发出 `layer_folder_requested.emit(layer_id)`。

菜单项始终显示、始终可点击（用户已确认：无本地文件的图层点击后由主窗口提示，而非禁用/隐藏）。

### 2. `main_window.py` — 打开文件夹

- `_connect_signals` 中连接 `self._layer_panel.layer_folder_requested.connect(self._open_layer_folder)`。
- 新增 `_open_layer_folder(layer_id: str) -> None`：
  - 从 `self._application.snapshot()` 查找该图层。
  - 找到且 `layer.source_path` 非空：`QDesktopServices.openUrl(QUrl.fromLocalFile(str(source_path.parent)))` 打开父目录。
  - `source_path` 为 None：状态栏提示"图层 {name} 没有本地数据文件"。
  - 图层不存在：静默忽略。

打开文件夹使用 Qt 标准 `QDesktopServices.openUrl`（跨平台、易测试），不做资源管理器选中文件高亮。

## 明确不做

- 不做 `explorer /select` 式文件选中高亮。
- 不做数据库图层的"打开数据库"入口。
- 不把路径缓存进图层树节点（snapshot 是唯一数据源）。
- 无撤销/重做（纯系统操作，不改变工作区状态）。

## 测试（新增 `tests/presentation/test_layer_open_folder.py`）

沿用现有 offscreen 测试模式（`QApplication.instance() or QApplication([])`、替换 `window._application`、无 pytest-qt）：

1. 有路径图层：monkeypatch `QDesktopServices.openUrl`，调用 `_open_layer_folder` 后断言以父目录 `QUrl` 调用一次。
2. 无路径图层（`source_path=None`）：断言 `openUrl` 未被调用、状态栏消息含"没有本地数据文件"。
3. 右键菜单含"打开文件夹"项且选择后信号携带正确 layer_id（monkeypatch `_execute_context_menu` 返回该 action，构造含两个图层的文档断言信号参数）。
