# GIS 桌面通用平台

基于 Python、PySide6、GeoPandas 和 Rasterio 构建的桌面 GIS 课程设计项目。平台采用经典 GIS 工作台布局，已经支持矢量与栅格数据的统一读取、显示和图层管理，并为查询编辑、空间分析及 PostGIS 数据管理集成了完整界面入口。

## 主界面

- 顶部功能区：文件、地图、编辑、分析、数据库和视图六个标签页，共 37 个入口。
- 左侧图层面板：显示真实图层，支持搜索、显隐切换和图层顺序管理。
- 中央地图画布：占据其余全部空间，不设置右侧预留面板。
- 底部状态栏：显示坐标、视图比例、当前图层、选择数量和坐标系。

## 支持格式

### 矢量

- `.shp`
- `.geojson`
- `.json`
- `.gpkg`（支持按图层名读取）
- `.kml`（WGS 84 经纬度，点/线/面及多重几何）

### 栅格

- `.tif` / `.tiff`
- `.img`
- `.dem`

大栅格采用“显示与分析分离”的读取策略：打开时只生成最长边不超过 2048 像素的
预览，完整波段值和有效掩膜在栅格计算或导出首次访问时按需加载；预览使用独立仿射
变换，仍覆盖原始数据的完整空间范围。

多波段遥感影像会自动选择显示波段、执行百分位拉伸，并将无数据背景设为透明。后续加载的图层会自动转换到当前地图工作区的显示坐标系。

在“视图 → 坐标系统”中可以输入 EPSG:4326、EPSG:3857 或 ESRI:102026
等 CRS 标识。已有图层会从原始数据源重新转换到新的地图 CRS；后续空间分析可通过
应用层分析环境指定独立的目标 CRS，准备临时输入副本而不修改工作区图层。

## 环境要求

- Windows 10/11
- Python 3.10–3.12
- [uv](https://docs.astral.sh/uv/)（推荐）

## 安装与启动

```powershell
uv sync
uv run python main.py
```

启动后进入“文件”标签页，点击“打开数据”选择本地矢量或栅格文件。仓库不包含测试数据，运行程序不要求 PostgreSQL/PostGIS 服务。

需要使用数据库时，在“数据库”标签页点击“连接数据库”，输入 PostgreSQL
连接参数；连接测试会同时验证 PostGIS。连接成功后，选择活动矢量图层点击“导入图层”，
或点击“加载图层”从数据库目录选择图层加入地图。“数据管理”可以查看数据库图层 ID、
几何类别和要素数量。数据库密码只在当前进程内使用，不会写入工程文件；当前从数据库加载的
图层不能直接写入 `.gisproj` 工程快照；如需随工程恢复，请先导出后重新打开导出的本地文件。

右键图层选择“符号系统”可打开右侧停靠面板。矢量支持单一符号、最多自动生成
100 类的唯一值符号，以及 3–7 级等间隔/分位数颜色；栅格支持 RGB 波段组合和
最小—最大值或百分比截断的单波段拉伸。符号修改自动生效，图例显示在图层树中。

右键矢量图层选择“标注”即可按默认名称字段在要素附近显示文本；选择“标注分类…”
可以创建多个标注类，为每一类指定标注字段、可选分类字段和值、九宫格位置、字号、偏移、
文字颜色以及可选的晕染底框。标注文字动态叠加在地图上，不会修改源数据文件；配置随工程保存，
字号和偏移按屏幕像素计算，缩放地图时会自动避让重叠标签。

选择活动图层后可点击“导出数据”指定本地输出位置。矢量图层存在选择集时只导出
选中要素，否则导出全部要素；栅格导出保留真实波段值、数据类型、NoData、空间参考
和地理变换，不使用地图显示时生成的拉伸 RGBA 缓存。

在“编辑”标签页点击“新增要素”下的点、线、面工具，会先弹出对话框列出当前
可承载该几何类型的矢量图层（默认选中活动图层），选择目标图层后在地图上
数字化绘制，新增的要素将追加到该图层并写回其源文件。绘制完成后弹出属性
表单，字段结构继承目标图层已有要素，也允许自行添加字段。目标图层要求为
Shapefile 或 GeoJSON 矢量图层；GeoPackage、KML 和数据库图层不会出现在
候选列表中。追加操作支持撤销/重做，数字化工具在完成后保持激活，可连续
追加多个要素。

在“分析 → 缓冲区分析”中选择矢量输入图层，填写输出图层名和文件位置，并设置
缓冲距离、圆弧分段数及可选结果融合。程序会识别输入图层的点、线、面几何类型：点图层
使用距离和融合参数；线图层额外提供两侧/左侧/右侧、端点样式、连接样式和斜接比；面图层
额外提供包含原面/仅外侧、连接样式和斜接比，并允许使用负距离向内缓冲。距离数值可自行选择
毫米、厘米、米、千米、英尺或英里，程序内部统一换算为米制投影坐标进行计算；经纬度图层会
自动选择本地米制计算 CRS，也可以手动指定投影 CRS。输出位置默认是输入数据的同一目录，
默认写出 GeoJSON；用户也可以浏览改为 Shapefile 或 GeoPackage。分析成功后结果会
自动作为新的活动图层加入“图层”面板并直接显示。

在“分析 → 分析记录”中可以按时间倒序查看当前工程的空间分析历史。记录会显示成功或失败状态，
悬停可查看输入图层、输出结果、执行时间、耗时和全部分析参数；清除记录
不会删除已经生成的结果图层和结果文件。分析历史与工程一起通过手动保存持久化。

地图全图范围只根据当前可见图层计算。隐藏大范围矢量图层后，栅格会自动适配到
自身范围；状态栏按坐标系实际权威来源显示，例如 `ESRI:102026`，不会误标为 EPSG。

不使用 uv 时可以通过 requirements 文件安装：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

## 开发检查

```powershell
uv run ruff check .
uv run mypy app
uv run pytest
```

当前基线为 87 项测试通过，覆盖领域图层、地图文档、应用服务、矢量与栅格读写器、
图层面板和 Qt 矢量渲染等已有能力。

工程文件使用 `.gisproj` 扩展名。工程文件保存图层路径、图层顺序、显隐状态、活动图层、
地图 CRS、视图状态和分析历史；分析结果默认可以写入工程目录下的
`project_data/results.gpkg`，同一 GeoPackage 中的每次分析使用不同图层名，旧结果不会被覆盖。
重新打开工程时会恢复结果图层和分析历史；如果输入文件的大小或修改时间发生变化，相关分析会
标记为可能过期，但不会自动重新运行。

## 项目结构

```text
gis_desktop/
├── app/
│   ├── application/          # 应用服务、端口和结果对象
│   ├── domain/               # 矢量、栅格、要素和地图文档模型
│   ├── infrastructure/       # GeoPandas、Rasterio、工程文件适配器
│   ├── presentation/         # 主窗口、功能区、面板、画布和渲染器
│   └── resources/styles/     # 全局 QSS 主题
├── tests/                    # 自动化测试
├── main.py                   # 应用入口
├── pyproject.toml            # 项目与工具配置
├── requirements.txt          # pip 依赖列表
└── uv.lock                   # 可复现依赖锁文件
```

## 架构

```text
用户界面层 → 应用服务层 → 领域模型层 ← 基础设施层
```

- 界面层只处理用户交互和 Qt 渲染。
- 应用服务统一编排图层管理、选择和外部数据读取。
- 领域模型不依赖 Qt，保存矢量、栅格及地图文档状态。
- 基础设施层通过 GeoPandas 和 Rasterio 适配具体文件格式。
